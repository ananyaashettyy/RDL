# AttendIQ - Attendance Management System

AttendIQ is a React-based attendance analytics and employee management UI with an optional PHP/MySQL backend and an Electron desktop build. By default, the UI reads attendance data from local JSON files and browser localStorage. The PHP backend is available for API integration and report upload workflows if you choose to enable it.

## Highlights

- Admin and User portals with separate login flows.
- Attendance dashboard with KPIs, charts, and monthly trends.
- Attendance detail view with late/early/overtime logic and per-day timelines.
- Reports page with PDF and CSV export generated in the browser.
- Masters for departments and sections.
- Team view with employee cards and attendance rate.
- Leave management and notifications stored in localStorage.
- Chatbot assistant for attendance and general questions.
- Electron desktop packaging for Windows.

## Tech Stack

- Frontend: React 18, React Router v6, Recharts
- Backend (optional): PHP 8 (XAMPP) + MySQL 8
- Desktop: Electron + electron-builder
- Storage: local JSON + browser localStorage
- Report parsing (optional): Python 3 + `openpyxl` + `xlrd`

## Architecture Summary

- React UI renders all dashboards and workflows.
- Attendance data is loaded locally from JSON and merged with employees.
- Admin and leave data persist in browser localStorage.
- Optional PHP backend provides REST endpoints and file upload.
- Optional Python parser converts Excel attendance logs into JSON.
- Electron wraps the React build for Windows desktop distribution.

## Data Sources and Storage

### Local data files

- `src/data/attendance_reports.json` contains attendance records keyed by employee ID and month. This file is generated by the report parser.
- `src/data/employees.js` defines employee metadata, departments, sections, and national holidays. It also includes a seeded attendance generator for sample data (months `2025-11` and `2025-12`).
- `src/data/attlogData.js` merges employees with attendance from `attendance_reports.json`.

If a record for an employee exists in `attendance_reports.json`, it overrides the seeded attendance data from `employees.js`.

### Browser localStorage keys

- `admin_users_v1`: Admin usernames and passwords.
- `attendance_rules_v1`: Late/early threshold times.
- `attendance_leaves_v1`: Leave entries keyed by `employeeId:YYYY-MM-DD`.
- `attendance_leave_notifications_v1`: Leave request notifications.

These values are local to the browser profile and are not shared across devices unless you add server-side persistence.

## Portals and Authentication

### Admin Portal

- Route: `/admin`
- Login uses admin credentials stored in localStorage.
- Default credentials: `admin` / `admin`.

### User Portal

- Route: `/user`
- Login is a simplified flow:
  - Username must be lowercase.
  - Password must be lowercase and match the username.
  - Username must be in the allowed user list derived from employee names.

Allowed usernames are generated from employee display names by taking the first name token and disambiguating duplicates by appending initials or extra letters.

### Access boundaries

User portal views are scoped to the logged-in employee. This is enforced in the UI and should not be treated as a secure boundary without backend enforcement.

## Frontend Pages and Routes

- Dashboard (`/admin/home`, `/user/home`): KPIs, attendance trends, and highlights.
- Attendance (`/admin/attendance`, `/user/attendance`): Daily in/out, late/early, overtime, and working hours.
- Report (`/admin/report`, `/user/report`): Detailed report with PDF/CSV export.
- Masters (`/admin/masters`, `/user/masters`): Department and section management.
- Team (`/admin/team`, `/user/team`): Employee cards and attendance rate.
- Admin (`/admin/admin`, `/user/admin`): Report upload and admin user management.
- Chatbot (`/admin/chatbot`): Assistant for attendance and general questions.

## Attendance Rules

- Default late threshold: `09:00`.
- Default early exit threshold: `17:00`.
- Rules are stored in localStorage under `attendance_rules_v1`.
- Late/Early flags are computed by comparing in/out times against these thresholds.

## Leave Management

Leave is handled locally in the browser:

- Leave types: `Paid Leave`, `Earned Leave`, `Training/Other Work Leave`.
- Leaves are stored in `attendance_leaves_v1`.
- Leave notifications are stored in `attendance_leave_notifications_v1`.
- Admin can accept or decline leave requests, which updates the stored leave entry.

## Reports and Exports

The Report page exports data entirely in the browser:

- CSV export: generates a file named `EmployeeName_YYYY-MM_report.csv`.
- PDF export: generates a file named `EmployeeName_YYYY-MM_report.pdf`.

No server upload is required for PDF/CSV exports.

## Chatbot

The chatbot supports attendance queries and general questions. It can:

- Answer attendance analytics across available months.
- Summarize department and employee metrics.
- Provide basic guidance or explanations for system behavior.

It does not modify attendance data or expose restricted information.

## Backend Database Schema (MySQL)

Database: `attendiq`

Tables:

- `departments`:
  - `id`, `name`, `description`, `created_at`
- `sections`:
  - `id`, `name`, `department_id`, `description`, `created_at`
- `employees`:
  - `id`, `emp_code`, `name`, `department_id`, `section_id`, `email`, `phone`, `join_date`, `status`, `created_at`
- `attendance`:
  - `id`, `employee_id`, `att_date`, `status`, `in_time`, `out_time`, `work_hours`, `idle_hours`, `created_at`
  - Unique key: `employee_id + att_date`

Seed data is included for departments, sections, and a subset of employees.

## Backend API Endpoints (PHP)

### Employees

- `GET /attendance-api/employees.php`
  - Optional query params: `id`, `dept`, `search`
- `POST /attendance-api/employees.php`
  - JSON body: `emp_code`, `name`, `department_id`, `section_id`, `email`, `phone`, `join_date`
- `PUT /attendance-api/employees.php?id=ID`
  - JSON body: `name`, `department_id`, `section_id`, `email`, `phone`, `status`
- `DELETE /attendance-api/employees.php?id=ID`
  - Soft delete (sets status to `inactive`)

### Attendance

- `GET /attendance-api/attendance.php?employee_id=ID&month=YYYY-MM`
  - Returns daily records and a summary (`present`, `absent`, `total`)
- `POST /attendance-api/attendance.php`
  - Upserts a daily record
  - JSON body: `employee_id`, `att_date`, `status`, `in_time`, `out_time`, `work_hours`, `idle_hours`

### Departments

- `GET /attendance-api/departments.php`
- `POST /attendance-api/departments.php`
  - JSON body: `name`, `description`
- `DELETE /attendance-api/departments.php?id=ID`

### Sections

- `GET /attendance-api/sections.php`
- `POST /attendance-api/sections.php`
  - JSON body: `name`, `department_id`, `description`
- `DELETE /attendance-api/sections.php?id=ID`

### Report Upload

- `GET /attendance-api/upload_reports.php?filename=Month_Year.xls`
  - Validates filename and checks if it already exists.
- `POST /attendance-api/upload_reports.php`
  - Multipart upload, processes Excel and regenerates `attendance_reports.json`.

## Admin Report Upload and Parsing

### Accepted file format

- Filename must be `Month_Year.xls` or `Month_Year.xlsx` with a full month name.
  - Example: `December_2025.xlsx`
- The parser expects a sheet named `Att.log report`.
- It reads a header row containing a date range like `YYYY-MM-DD ~ ...`.

### Punch parsing logic (Excel)

- Extracts all `HH:MM` values in a cell.
- Removes near-duplicate punches (within 3 minutes).
- Normalizes to up to 4 times per day:
  1. In time
  2. Logout for lunch (optional)
  3. Login from lunch (optional)
  4. Logout
- Work time is computed as `logout - in_time` minus lunch break if present.

### Output

- Generates `src/data/attendance_reports.json` with structure:
  - `{ employeeId: { YYYY-MM: [ { day, status, inTime, logout, ... } ] } }`
- Status defaults:
  - Weekends are `weekend` (Saturday and Sunday).
  - Weekdays default to `absent` until punches are found.

## Optional Backend Setup (PHP + MySQL via XAMPP)

1. Start XAMPP and enable Apache + MySQL.
2. Import database:
   - Open `http://localhost/phpmyadmin`
   - Import `backend/schema.sql`
3. Deploy backend:
   - Copy `backend/` to `C:\xampp\htdocs\attendance-api\`
4. Test endpoint:
   - `http://localhost/attendance-api/departments.php`

The React app sets a proxy in `package.json`:

- `"proxy": "http://localhost/attendance-api"`

Currently the UI only calls `upload_reports.php` for report uploads. Core data still reads from local JSON unless you wire API calls.

## Parser Setup (Optional)

The report upload uses a Python script to parse Excel files.

Install dependencies:

```bash
pip install openpyxl xlrd
```

Run manually (optional):

```bash
python scripts\parse_attlog_reports.py
```

The parser reads from `uploads/` and updates `src/data/attendance_reports.json`.

## Troubleshooting

- Admin upload not working in desktop build: The upload flow is disabled when the app runs from `file://`.
- Parser failures: Ensure `openpyxl` and `xlrd` are installed and that the Excel sheet name is `Att.log report`.
- API calls failing: Ensure XAMPP is running and the backend is deployed to `C:\xampp\htdocs\attendance-api\`.
- Login issues: Admin credentials are stored in localStorage and may have been changed. Clear localStorage to reset to defaults.

## Known Limitations

- Backend endpoints are not fully wired into the React data flow.
- Admin users and leave data are stored in browser localStorage (not server-side).
- User portal access control is UI-level only.
